# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Product purpose

OpenSP documents the SP-404MKII firmware project and provides a home for its
guides, tools and eventual firmware releases. A reader should be able to follow
what was tried, what the evidence established, and what remains unknown.

## Users

The owner requested programming-style guides about the project's journey.
For the first article, the working audience is curious SP owners, with short
explanations for readers new to firmware analysis. This audience emphasis is
an editorial assumption pending the owner's answer, not a confirmed requirement.

## Capabilities and constraints

The approved stack is a static Astro site on GitHub Pages. Keep navigation
native and browser scripts small. The public website never connects to the SP.
Penpot supplies the shared visual system and linked components. Changes are
explicitly exported and reviewed; no automatic two-way synchronization exists.

## Brand commitments

Keep OpenSP's monochrome, sharp-line instrument diagrams, Arimo reading text,
Cousine navigation and labels, and the owner's Teenage Engineering references.
Desktop, mobile, light and dark views share content and components.

## Evidence on hand

The local research workspace preserves firmware manifests, IDA exports, CPU
verification reports and owner-reported hardware results. Publish only reviewed,
project-relevant extracts. Do not publish firmware binaries, private identity
metadata, local account paths or credentials. Illustrative screens must be
labeled as reconstructions; they are not device photographs or captures.

## Accessibility

Guides must work without JavaScript. Use semantic headings and links, keyboard
controls, readable contrast and reduced-motion behavior. Animations are optional
explanations and cannot be the only way to learn a result.
